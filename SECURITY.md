# Security

For security reports, use GitHub's private vulnerability reporting when it is available on this repository. Otherwise, open an issue that asks for a private contact route without including credentials or exploit details.

Hext 0.7.3 and later do not download or install audio add-ons. Keep Windows' normal download and application checks enabled.

Assistant adapters use installed CLIs and their authentication. Never attach session files, API keys, login output, or a personal `hext.ini` to an issue. Redact personal paths from logs and screenshots.

Only the current release is maintained. The application is currently unsigned. Hext has not undergone an independent security audit.

The assistant validates a typed, extensible host tool catalog and enforces permissions in native code. Prompts are not a security boundary. Codex requests restricted filesystem/network execution and checks a compatible Windows sandbox; incompatible installations fail closed. Claude requires restricted/safe mode and empty tools/MCP configuration. Provider executables and administrator-managed policy must be trusted; these controls do not protect against a compromised CLI or malware running as the user.

Private payloads use current-user DPAPI encryption and a restricted directory ACL under LocalAppData. Preference memory is separate from history. Both can be deleted in settings. Provider retention and global sign-ins remain provider-controlled. See [privacy and removal](docs/assistant.md#privacy-and-removal).

Spotify uses PKCE, loopback state validation, encrypted tokens, fixed HTTPS endpoints, and no client secret. Disconnect deletes local tokens and caches; server-side revocation uses Spotify's account page. Spotify metadata is not sent to the model, and Spotify voice control is refused.

Task preparation and execution are separate. Three global modes replace category/service/tool grants: ask, independent AI review, or automatic routine execution. Old preferences migrate to ask. Every native adapter uses the same gate; model prose cannot grant authority. Review uses the protected selected CLI and an exact goal/action pair, never unrestricted provider tools. Missing, invalid, uncertain, or timed-out review asks the user. Human and reviewer permits are distinct, request/chat/revision-bound, expiring, and one-use. High-risk actions cannot consume a reviewer permit. Skills are reviewed JSON compositions of existing tools, not executable plugins; recursion, unknown tools, code, and schema changes are rejected. Native-scoped media target fields cannot be supplied in model JSON. Native adapter modules must be reviewed and compiled into Hext; the application does not download or load arbitrary MCP servers or DLLs.

Authorized text operations remain bounded and reject scripts, path traversal, unsupported types, and overwrites. Revoking an authorized parent folder invalidates derived item IDs. External writes already accepted cannot be undone by canceling. See [task boundaries](docs/tasks.md).

Interactive chat requests are host-created presentation, not a second permission engine. Native button bindings include the component, conversation, task, revision and current approval nonce, and are invalidated after a decision. History serialization excludes those bindings and tickets. Restored pending components cannot execute; explicit resumption uses the existing durable task recovery and new authorization. Provider output remains plain text/typed tool requests and cannot manufacture a native approval control. Rendering clips hit targets as well as pixels so hidden chat controls do not intercept composer/navigation input.

Native authorization bodies/details are local presentation, not automatic provider context. The provider receives bounded kind/state/title summaries of these components; actual tool receipts and authorized results retain their existing gates. This avoids disclosing a selected absolute path just because its approval card was rendered before the user decided.

General PowerShell is a separate host tool confined to a unique AppContainer without network capability SIDs or personal-folder grants. UI automation runs in bounded owned workers and checks window/process identity and observed control state. Benign scoped operations follow the global mode; unknown invocations, known financial/critical controls, and recognized sensitive disclosure still require user consent. These classifications are conservative, incomplete heuristics, not universal semantic safety. Recognized sensitive results are held before provider context and checkpoint result data, then released only with one-use sharing consent. These channels do not enable provider-owned tools. Package installation requires a signature/source-checked WinGet executable, exact version proposal and explicit approval. Task checkpoints are encrypted; resumed tasks discard old tickets and never blindly replay an interrupted operation. See [agent boundaries](docs/agent.md), including UI classification and disk-quota limits.
